# AGENTS.md

This file provides guidance to Claude Code (and other AI coding agents) when working with code in this repository.

## Project

Website for **Desiray's Lights of Joy** (desirayslightsofjoy.org), a San Diego nonprofit that donates personalized 30" neon lights to pediatric patients ("Young Warriors") undergoing bone marrow / stem cell transplant at Rady Children's Hospital. The nonprofit was founded in memory of Desiray Joy, the founder's daughter, who had Down syndrome. Desiray's favorite color was pink ("Buffalo girl") — pink/neon-glow is the core brand motif. The board wants to maintain and tweak this site themselves going forward.

There is no build system, framework, or package manager — this is a static HTML/CSS/vanilla-JS site deployed on Vercel. There is nothing to install, build, lint, or test; edit the files in `html/` directly and open them in a browser (or run a static file server) to preview.

To preview locally:
```
cd html && python3 -m http.server 8000
```

## Architecture

- `html/*.html` — one file per page: `index.html`, `about.html`, `donate.html`, `contact.html`, `what_we_do.html`, `child.html`. Every page shares the same `style.css` and `script.js` via `<link>`/`<script>` tags — there is no templating, so shared markup (nav, footer, theme toggle button) is duplicated across every HTML file. When changing shared UI (nav, footer, theme toggle), update it in every page file, not just one.
- `html/style.css` — single global stylesheet (~2800 lines). Theming is done via CSS custom properties defined on `:root` (light/default) and overridden under `[data-theme="dark"]` (the site's "lights-off" dark mode, selected by `localStorage.dloj_theme` and toggled per-page by a `nightModeToggle*` button — see `script.js`). Key variable groups: `--rose-*` (brand pink palette), `--bg-*`, `--text-*`, `--shadow-*`, `--neon-*-glow` (box/text-shadow glow effects), `--font-*`.
- `html/script.js` — one shared vanilla-JS file handling cross-page behavior: dark/"lights-off" mode toggle, the Wall of Hope guestbook (messages persisted to `localStorage.dloj_messages`, rendered via manual DOM/innerHTML with an `escapeHTML` helper — keep using it for any new user-generated text to avoid XSS), donate quick-amount tiles, mobile nav menu, and the contact form (client-side only, no backend — just shows an alert).
- `html/child.html` + `html/child.js` — a single templated page for every donated light. `child.js` reads `window.DLOJ_CHILDREN` (loaded from `html/assets/data/children.js`) and renders the child's name/photo/note based on a `slug`. The slug is resolved either from the `/light/:slug` path (rewritten to `/child` by `html/vercel.json`) or from a `?c=`/`?child=`/`?name=`/`?slug=` query param (used for local preview without the Vercel rewrite). Prev/Next and the "Explore more" grid are generated by walking the `DLOJ_CHILDREN` array circularly from the current index.
- `html/assets/data/children.js` — the single source of truth for every donated light: `{slug, name, img, alt, note, founder?}`. To add a new light/child, append an entry here and drop the photo in `html/assets/images/what-we-do/`; no other file needs to change — `child.html`/`child.js` picks it up automatically, and the page becomes reachable at `/light/<slug>`.
- `html/vercel.json` — Vercel config: `cleanUrls`, no trailing slash, and the `/light/:slug` → `/child` rewrite that makes per-child pages work in production (destination must be `/child` without `.html` because `cleanUrls: true` is enabled).

There is no donation counter wired to real data yet — treat any "lights donated" figure in the markup as static copy to be updated by hand until a real data source exists.
